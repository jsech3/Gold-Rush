1. What Gold Rush Does

Gold Rush runs twice a day, pulls jobs from three sources, scores them, and emails you a ranked digest. Every job is stored in a local database whether it makes the email or not.

Daily Flow

TimeWhat Happens
7:30 AMtpm_job_hunter.py scrapes Hacker News "Who's Hiring" → CSV
8:00 AMgold_rush.py reads all 3 sources → scores → emails digest
7:00 PMgold_rush.py runs again to catch afternoon postings

2. Three Job Sources

SourceHow It WorksLabel in Email
LinkedIn / Indeed / Glassdoor Alerts Logs into Gmail via IMAP, reads job alert emails from the last 24 hours, parses title, company, location, and salary from the HTML LinkedIn Alert / Indeed Alert / Glassdoor Alert
JSearch API 3 API calls per run to jsearch.p.rapidapi.com. Searches your target titles × locations. Free tier: 200 requests/month (~6/day = ~180/month) Online (JSearch)
Hacker News Reads CSV produced by tpm_job_hunter.py. Filters to analyst roles, US-only, skips engineers/designers/interns Hacker News
Each job in the email shows its source (e.g., "Found via: LinkedIn Alert") so you always know where it came from.

3. Scoring System (0–100)

Each job is scored on six factors. The score determines its tier and where it appears in the email.

FactorMax PointsLogic
Title match35 Business Data Analyst = 35, BI Analyst = 33, Business Analyst = 32, Data Analyst = 30, Operations Analyst = 29. Partial match ("analyst" + "data") = 24
Salary25 $180K+ = 25, $150K+ = 22, $120K+ = 18, $100K+ = 14, $80K+ = 8, lower = 4, unknown = 5
Freshness15 <6hrs = 15, <12hrs = 12, <24hrs = 9, <48hrs = 5, older = 2
Company quality10 Preferred list (Stripe, Anthropic, etc.) = 10, known tech (60+ companies) = 7, unknown = 3
Location match10 Remote or SF = 10, South Bay = 8, California = 6, other US = 3, unknown = 4
Seniority fit5 Senior/Lead = 5, Mid-level = 4, Staff/Director = 3, Intern/Junior = 1

Tiers

TierScoreIn Email?
Platinum85–100Yes — top of digest, highlighted
Gold70–84Yes — featured section
Silver50–69Yes — listed
Bronze<50No — stored in DB only
Safety net: Score floor is 30 — a title match alone guarantees a job won't be invisible. Silver threshold is 50, so borderline jobs still make the email.

4. Email Digest

Each job card in the email shows:

  • Job title and company
  • Location
  • Salary (if available, or "Salary not listed")
  • Score out of 100
  • Source label (LinkedIn Alert, Online, Hacker News, etc.)
  • Apply Now button — links to the job listing
  • I Applied button (green) — for tracking applications

"I Applied" Tracking

  1. You apply to a job normally
  2. Tap the green "I Applied" button in the email
  3. It opens a pre-filled email draft (subject: APPLIED:#47 - Data Analyst at Stripe)
  4. Hit Send
  5. Next time Gold Rush runs, it scans your inbox for APPLIED: emails, marks them in the database, and removes them from future digests
One tap + Send. No SQL, no command line. Jobs you've applied to automatically stop appearing.

5. Your Daily & Weekly Workflow

Morning Routine (10–15 min)

StepWhat to DoTime
1 Check your inbox for the Gold Rush digest (arrives ~8:00 AM) 1 min
2 Scan Gold-tier jobs first — these are your best matches (right title, good salary, strong company). Open any that interest you. 2 min
3 Apply to your top 2–3 picks. Focus on Gold-tier and high Silver-tier. Don't agonize — speed matters more than perfection for early applications. 8–10 min
4 Tap "I Applied" on each job you applied to. Hit Send on the draft. This removes them from future digests. 30 sec

Evening Check (2–5 min)

StepWhat to DoTime
1 Check the 7 PM digest — catches jobs posted during the day 1 min
2 Apply to 1–2 more if anything stands out. Don't force it if nothing's great. 2–4 min
3 Tap "I Applied" for any you applied to 15 sec
Daily target: 3–5 quality applications per day. That's 15–25 per week, 60–100 per month. Consistency beats volume.

Weekly Review (15 min, pick any day)

StepWhat to DoWhy
1 Check your applied count:
sqlite3 $HOME/GoldRush/gold_rush.db "SELECT COUNT(*) FROM jobs WHERE applied = 1;"		 Track your pace. Are you hitting 15–25/week?
2 Spot-check scoring: Were Gold-tier jobs actually good? Were good jobs landing in Bronze? If scoring feels off, adjust TARGET_TITLES or PREFERRED_COMPANIES in config.env
3 Check system health:
launchctl list | grep gold_rush
tail -5 $HOME/GoldRush/logs/launchd.err.log		 Make sure both daily runs are firing. Exit code should be 0.
4 Review companies you're seeing. Add any new dream companies to PREFERRED_COMPANIES. Add any junk companies to AVOID_COMPANIES. Keeps the scoring tuned to your preferences over time

What NOT to Do

  • Don't apply to everything. Bronze-tier jobs aren't in the email for a reason. Focus on Silver+ unless you're casting a very wide net.
  • Don't skip "I Applied." If you don't mark jobs, they'll keep showing up and clutter future digests.
  • Don't manually search LinkedIn/Indeed on top of this. Gold Rush already reads those alerts. You'd just be duplicating effort.
  • Don't ignore the evening digest. Afternoon postings are less competitive — fewer people applying at 7 PM.

6. Database

File: $HOME/GoldRush/gold_rush.db (SQLite)

Every job ever found is stored here, regardless of tier. Key columns:

ColumnDescription
idAuto-increment ID (used in "I Applied" links)
title, company, locationParsed job details
salary_min / salary_maxParsed salary range (null if not listed)
sourcelinkedin_email, indeed_email, glassdoor_email, jsearch_api, hacker_news
goldness_score / tier0–100 score and platinum/gold/silver/bronze
found_dateWhen Gold Rush stored it
emailedWhether it was included in a digest
appliedWhether you marked it via "I Applied"

Useful Queries

cd $HOME/GoldRush # All Gold+ jobs you haven't applied to sqlite3 gold_rush.db "SELECT title, company, goldness_score FROM jobs WHERE tier IN ('gold','platinum') AND applied = 0 ORDER BY goldness_score DESC;" # Jobs found today sqlite3 gold_rush.db "SELECT title, company, source, tier, goldness_score FROM jobs WHERE DATE(found_date) = DATE('now') ORDER BY goldness_score DESC;" # Source breakdown sqlite3 gold_rush.db "SELECT source, COUNT(*), ROUND(AVG(goldness_score),1) FROM jobs GROUP BY source;" # Jobs per day sqlite3 gold_rush.db "SELECT DATE(found_date), COUNT(*) FROM jobs GROUP BY DATE(found_date) ORDER BY DATE(found_date);" # Applied jobs sqlite3 gold_rush.db "SELECT title, company, found_date FROM jobs WHERE applied = 1 ORDER BY found_date DESC;"

9. Scheduler Details

Gold Rush uses macOS launchd to run automatically. The plist lives at:

~/Library/LaunchAgents/com.yourname.gold_rush.plist

SettingValue
Python/opt/homebrew/opt/python@3.13/bin/python3.13
Script$HOME/GoldRush/gold_rush.py
Schedule8:00 AM and 7:00 PM daily
Logs$HOME/GoldRush/logs/
Important: The project was moved from Desktop/... to $HOME/GoldRush/ to avoid macOS Desktop permission restrictions. The plist must point to the Homebrew Python (not /usr/bin/python3) because the system Python doesn't have the required packages.

10. Common Commands

Run Manually

cd $HOME/GoldRush python3 gold_rush.py

Check Recent Logs

tail -30 $HOME/GoldRush/logs/gold_rush.log

Check If Scheduler Is Running

launchctl list | grep gold_rush # Exit code 0 = healthy. Exit code 2 = error.

Check Scheduler Errors

tail -10 $HOME/GoldRush/logs/launchd.err.log

Stop the Scheduler

launchctl unload ~/Library/LaunchAgents/com.yourname.gold_rush.plist

Restart the Scheduler

launchctl unload ~/Library/LaunchAgents/com.yourname.gold_rush.plist launchctl load ~/Library/LaunchAgents/com.yourname.gold_rush.plist

Force a Run via Scheduler (Test)

launchctl kickstart gui/$(id -u)/com.yourname.gold_rush

11. Troubleshooting

ProblemCheckFix
No email received tail -30 logs/gold_rush.log If no recent entry, scheduler isn't running. Run launchctl list | grep gold_rush. If missing, reload the plist.
Scheduler shows exit code 2 tail -10 logs/launchd.err.log Usually a Python path or permissions issue. Verify the plist points to /opt/homebrew/opt/python@3.13/bin/python3.13
"Operation not permitted" launchd.err.log Script is in a macOS-protected folder. Must live in $HOME/GoldRush/ (not Desktop)
"No module named requests" launchd.err.log Plist is using wrong Python. Must use Homebrew Python, not /usr/bin/python3
JSearch API timeout gold_rush.log shows timeout errors Intermittent — the API is flaky. Will retry next run. Not a problem unless it happens every time.
Email went to spam Check Gmail spam folder Mark "Not Spam". Create filter: From your-email@example.com → Never send to spam
All jobs score the same Check if salary/location are empty in DB Parser issue. Run sqlite3 gold_rush.db "SELECT title, company, location, salary_min FROM jobs ORDER BY id DESC LIMIT 10;"
"I Applied" not working Check if APPLIED: emails are in your inbox Gold Rush scans for them on each run. They must be in your inbox (not drafts). The subject must start with APPLIED:#

12. How to Customize

Want To...Do This
Add/remove job titles Edit TARGET_TITLES in config.env
Add preferred companies Edit PREFERRED_COMPANIES in config.env
Block a company Edit AVOID_COMPANIES in config.env
Change search locations Edit TARGET_LOCATIONS in config.env
Reduce API usage Lower MAX_JSEARCH_CALLS_PER_DAY (currently 3)
Change run times Edit Hour/Minute in ~/Library/LaunchAgents/com.yourname.gold_rush.plist, then reload
Add more LinkedIn alerts Create alerts on linkedin.com/jobs — Gold Rush auto-reads any alert email from LinkedIn
No restart needed for config.env changes. The script re-reads config.env on every run, so changes take effect at the next 8am or 7pm run.

13. Quick Health Check

Run these three commands to verify everything is working:

# 1. Is the scheduler loaded? launchctl list | grep gold_rush # Want: exit code 0 # 2. When did it last run? tail -3 $HOME/GoldRush/logs/gold_rush.log # Want: recent timestamp + "Gold Rush completed successfully" # 3. Any errors? tail -3 $HOME/GoldRush/logs/launchd.err.log # Want: empty or old errors
If all three look good, Gold Rush is healthy. If not, check the Troubleshooting section above.
